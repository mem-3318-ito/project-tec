# LWC移行観点レビュー

単純な文法チェックではなく、設計・デザイン実装・LWC移行観点でコードをレビューする。

## 報告の優先順位

課題は以下の優先順位で報告すること。

1. デザイン実装（基本方針であるカスタムCSSに沿っているか。SLDS v1を利用している場合はその適切性）/ アクセシビリティ（WCAG 2.1 AA）
2. LWC移行時のリスク
3. コンポーネント境界 / メンテナンス性（共通コンポーネントの範囲を逸脱していないか含む）
4. CSSの漏洩（リーク）
5. JavaScriptとDOMの結合度（コンポーネントを跨ぐ処理がイベント経由で疎結合になっているか）
6. 軽微なスタイルの問題

## チェック項目

- デザイン仕様どおりに実装されているか（基本はカスタムCSSでの実装）
- SLDS v1を利用している場合、SLDS Blueprintに準拠しているか
- SLDS v1を利用している場合、SLDSクラスを直接overrideしていないか
- 独自CSSがコンポーネント単位で閉じているか（汎用的すぎるクラス名になっていないか）
- コンポーネント境界が適切か
- 将来LWC化しやすいDOM構造か
- JavaScriptがコンポーネント境界を越えていないか
- id依存になっていないか
- inline CSS / inline JSがないか
- アクセシビリティ要件（WCAG 2.1 AA）を満たしているか
- 不要なHTML階層がないか
- Includeが過剰にネストされていないか
- Lightning Base Componentへ置き換えやすい構造か
- 共通コンポーネント（ヘッダー / グローバルナビゲーション / パンくずリスト / 戻るボタン）以外を安易に共通化していないか
- コンポーネントを跨ぐ処理をカスタムイベント経由でページ側に仲介させているか（コンポーネント同士が直接DOM操作していないか）

SLDS v1を利用している箇所との詳細な整合性確認が必要な場合は `.claude/skills/slds-check` を使うこと。

各項目の判断基準・実装ルールの詳細は `.claude/rules/slds-static-ui.md` を参照。
